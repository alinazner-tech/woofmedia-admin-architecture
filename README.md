# WoofMedia – адмін-панель: від промпту до перевіреної архітектури

Тут три речі, повʼязані одна з одною:

1. **[Промпт](docs/PROMPT.md)**, який дають агенту, щоб той спроєктував фронтенд адмін-панелі WoofMedia.
2. **[Архітектура](docs/ARCHITECTURE.md)**, яку агент за цим промптом видав, – після рев'ю.
3. **Код і тести**, які доводять, що ця архітектура працює, а не просто гарно звучить.

Промпт пройшов чотири ітерації. Кожну версію прогнано через агента, результат розібрано, помилки
враховано в наступній. Усі проміжні версії і результати лежать у [docs/prompt-evolution](docs/prompt-evolution).

## Запустити за хвилину

```bash
npm ci
npm run dev
```

Відкрийте http://localhost:5173 і увійдіть одним із тестових користувачів: два спеціалісти з різних
команд, тімлід і супер-адмін. Бекенду не треба – його замінює еталонний мок шлюзу (про нього нижче).

Щоб «покласти» сервіс і подивитися, як панель деградує частинами:

```bash
curl -X POST localhost:5173/api/__dev/down -H 'Content-Type: application/json' \
  -d '{"service":"checklists","down":true}'
```

## Перевірити все

```bash
npm run verify
```

Одна команда проганяє все:

| Крок | Що доводить |
|---|---|
| `typecheck` | Типи сходяться, strict-режим |
| `lint` | Межі модулів: спеціалістський код не може імпортувати адмінський (Б-8) |
| `test` | 57 тестів: юніт, компонентні, контрактні |
| `build` + `check:chunks` | У зібраному бандлі код фінансів, моніторингу й промптів недосяжний для спеціаліста (Б-3а) |
| `e2e` | 11 сценаріїв у справжньому Chromium проти зібраного бандла |

## Що тут НЕ доведено – і чому це чесно

Безпеку даних забезпечує бекенд: спеціаліст не отримує чужого проєкту, фінанси не віддаються,
недозволений перехід відхиляється. Тест фронтенду з моками про це **нічого не доводить** – і в документі
це прямо розведено: такі інваріанти позначені **СТЕНД**.

Для них є [контрактні тести](tests/contract/contract.test.ts) (Б-1, Б-2, Б-4, Б-5, Б-6, Б-12с, Б-13, Б-14).
Локально вони йдуть проти еталонного моку й доводять лише одне: контракт несуперечливий і виконуваний.
Проти справжнього стенду ті самі тести запускаються так:

```bash
CONTRACT_BASE_URL=https://api.stage.example \
CONTRACT_TOKENS='{"spec-a":"…","spec-b":"…","lead-a":"…","client-1":"…"}' \
npm run test:contract
```

Тоді вони доводять саме те, що треба.

## Еталонний мок шлюзу

[`mock/gateway.ts`](mock/gateway.ts) – це не бекенд WoofMedia. Це Додаток А архітектури («контракт до
бекенду»), записаний так, щоб його можна було виконати. Один обробник запитів обслуговує dev-стенд,
тести фронтенду й контрактні тести – тому моки і контракт не можуть тихо розійтися.

## Що знайшли тести

Під час перевірки знайшлися три справжні дефекти. Усі виправлено, кожен тепер закритий тестом:

1. **Дані попереднього користувача переживали повторний вхід.** Якщо на спільному компʼютері вхід
   виконувала інша людина без явного виходу, меню й кеш лишалися від попередньої. Тепер кеш очищується
   при кожному вході.
2. **«Вийти» не розлогінював інші вкладки.** Механізм синхронізації вкладок існував і проходив юніт-тест,
   але кнопка його не викликала. Знайшов лише e2e у двох справжніх вкладках.
3. **Після деплою замість сторінки – порожнеча.** Якщо старий chunk зник із CDN, React Router не показує
   межу помилки для ледачого маршруту. Тепер збій завантаження обробляється всередині `lazy()`.

Ще шість місць, де помилявся сам документ архітектури, описані в його кінці («Правки рев'ю»)
і враховані в промпті v4.

## Структура

```
docs/
  PROMPT.md               фінальний промпт (v4)
  ARCHITECTURE.md         архітектура після рев'ю
  prompt-evolution/       промпти v1–v3 і те, що агент за ними видав
src/
  app/                    вхід, маршрути (єдине місце lazy-імпорту модулів), оболонка, екрани помилок
  modules/                queue, project – робочі; finance, monitoring, prompts – адмінські
  entities/               project, user – спільне для кількох модулів
  shared/                 HTTP-клієнт, сесія, час, i18n, UI – нічого не знає про домен
mock/gateway.ts           еталонний мок шлюзу = виконуваний контракт
tests/                    unit, contract, фікстури-порушники для лінтера
e2e/                      сценарії в Chromium
scripts/check-chunks.ts   перевірка графа chunk після збірки
```

Стек: React 19, TypeScript, Vite, TanStack Query, React Router, Vitest, Playwright, oxlint.
Фронтенд – статичні файли для S3/CloudFront, без власного серверного процесу.
